## Regression: sms-stats opt-out filter uses wrong column name

**File:** `product/lead-response/dashboard/app/api/analytics/sms-stats/route.ts`  
**Line:** ~140  

**Before (correct):**
```javascript
.filter((m: any) => !isOptOut(m.message_body))
```

**After (incorrect, introduced by this branch):**
```javascript
.filter((m: any) => !isOptOut(m.body))
```

**Why this is wrong:**
- The `sms_messages` DB table has a column named `message_body`, NOT `body`. This is confirmed by:
  1. The `sms-optout-column.test.js` integration test (which queries the live DB schema)
  2. Line 121 of the same file: `.select('lead_id, message_body, ...')` — the query selects `message_body`
  3. The comment on line 118 which originally stated "Use message_body column"

**Impact:** Silent runtime bug — all inbound messages would return `undefined` for `m.body`, causing `isOptOut()` to always return `false`. This means opt-out replies would be counted as real replies, inflating reply rate metrics.

**Fix required:** Change `m.body` back to `m.message_body` on line ~140.
