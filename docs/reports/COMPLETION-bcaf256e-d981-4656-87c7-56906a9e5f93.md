## Summary

Fixed the `replenishQueue` startStep calculation bug that caused infinite task recreation loops for UCs with `implementation_status='ready'`.

## Problem

The `replenishQueue()` function in `heartbeat-executor.js` was only calculating `startStep` for UCs with statuses `['stuck', 'in_progress', 'not_started']`. When a UC had status `'ready'`, the `startStep` variable remained at 0, causing the orchestrator to recreate step-0 tasks (typically PM tasks) even when those steps had already been completed.

This led to:
- Duplicate PM tasks being created for the same UC
- Infinite task recreation loops
- Wasted compute resources
- Blocked workflow progression

## Solution

Added `'ready'` to the status filter array on line 7515 of `core/heartbeat-executor.js`:

```javascript
// Before:
if (['stuck', 'in_progress', 'not_started'].includes(uc.implementation_status)) {

// After:
if (['stuck', 'in_progress', 'not_started', 'ready'].includes(uc.implementation_status)) {
```

This ensures that `startStep` is calculated correctly for all UC statuses that should trigger workflow progression.
