## Gaps & Issues

### SECURITY GAP: Admin API routes have no authentication
- `GET /api/admin/pilot-campaigns` — no auth
- `GET/POST /api/admin/pilot-campaigns/[id]/targets` — no auth
- `GET /api/admin/pilot-campaigns/[id]/stats` — no auth
- `PATCH /api/admin/pilot-targets/[id]` — no auth

The Next.js middleware matcher excludes `/api` routes entirely (`(?!api|...)`), so middleware-level auth does not cover these. This matches the pattern of 6 other pre-existing admin routes that also lack auth (e.g., `/api/admin/conversations`, `/api/admin/simulate-lead`). This is a systemic gap, not unique to this PR. However, pilot recruitment data (names, emails, social profiles) is PII — unauthenticated access is a real exposure risk.

**Recommended fix:** Add `verifyAdminSession()` or `requireAuth()` to all admin API route handlers. Create a tracked issue.

### Dead Code: routes/pilot-campaigns.js
- Complete Express route implementation exists but is never registered in server.js
- All actual serving is done via Next.js API routes
- This file should either be deleted or registered

### Migration numbering conflicts (pre-existing)
- Two `005_*`, two `007_*`, two `009_*` migrations exist
- Not introduced by this PR but the pattern is worsening

### test-results/ binary files committed
- 60+ test-results PNG/MD files are committed on the branch
- .gitignore does not cover `test-results/` in dashboard
- Should be added to .gitignore
