## Root Cause

The acceptance check `check-dist-channels` for `uc-distribution-loop-fix` used the command:
```
psql -c "SELECT COUNT(*) FROM distribution_channels WHERE ..."
```

This failed because `psql` is **not in PATH** when run via `execSync` in heartbeat-executor — the binary lives at `/opt/homebrew/Cellar/postgresql@16/16.13/bin/psql`.

The `distribution_channels` table was correctly seeded (had 1 active `landing_page` row for `leadflow`), so the data was fine — only the check command was broken.

---

## Fix Applied

Updated the `acceptance_checks` JSONB column in the local postgres `use_cases` table for `uc-distribution-loop-fix` to use the full psql path and explicit DB connection string:

**Before:**
```json
[{
  "id": "check-dist-channels",
  "command": "psql -c \"SELECT COUNT(*) FROM distribution_channels WHERE project_id='leadflow' AND channel_type='landing_page' AND status='active'\"",
  "expected": "1"
}]
```

**After:**
```json
[{
  "id": "check-dist-channels",
  "command": "/opt/homebrew/Cellar/postgresql@16/16.13/bin/psql \"postgresql://clawdbot@localhost/openclaw\" -tAc \"SELECT COUNT(*) FROM distribution_channels WHERE project_id='leadflow' AND channel_type='landing_page' AND status='active'\"",
  "expected": "1"
}]
```
