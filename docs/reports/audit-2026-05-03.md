## 2. Why Genome Missed Each One

Mapping each gap to genome detection layers and the failure mode:

### Gap 1 — No logout button in nav
- **No UC ever existed** for "logout button." PM agent reasons about explicit user requests, not flow completeness.
- **Journey review** would catch this (the `new-agent-signup` journey explicitly walks the dashboard) — **but the journey review pipeline is stale**, latest completed 2026-03-17 (47 days).
- **E2E `dashboard-no-errors`** in `scripts/e2e-flow-tests.sh:176` only checks the page renders without error strings. No assertion on UI elements like a logout testid.
- **Root cause:** PM coverage is reactive (asks → UC → task), not flow-completeness-driven.

### Gap 2 — Admin auth fragmentation
- Each admin endpoint shipped via separate UC (e.g. `feat-add-auth-middleware-to-protect-dashboard` 2026-04-11; `fix-admin-admin-pilots-page-has-no-authentication-protection` 2026-04-06). Each dev picked an auth pattern in isolation.
- **No codebase rule** forces a single shared `requireAdmin()` import across `app/api/admin/**` and `routes/admin/**`. The existing `codebase_rules` (`project.config.json`) target Supabase removal and the auth-token cookie — not admin-route uniformity.
- **Code review** (kimi/sonnet QC) reviews one PR at a time; doesn't compare against patterns across files.
- **Root cause:** missing systemic constraint.

### Gap 3 — Trial-expired redirect goes to /pricing
- **Two UCs both marked "complete" while the flow is broken end-to-end:**
  - `uc-dashboard-trial-countdown` (Dashboard: Trial Expiration Countdown & Upgrade CTA) — complete 2026-03-31. Built `app/dashboard/trial-expired/page.tsx`.
  - `feat-trial-conversion-nudge` (Trial Expiry Conversion Nudge) — complete 2026-04-08.
- **Middleware never wired** to redirect to `/dashboard/trial-expired`. PR #1317 (`feat-conversion-call-booking`) added conversion CTAs to that page — without anyone noticing nothing reaches it.
- **E2E test** for trial-expired (`tests/unit/trial-to-paid-conversion.test.js:84-89`) is `assert.ok(fs.existsSync(trialPath))` — a file-existence check, not a flow test. **Per genome's own QC rule "no string-match tests" — this test should have been rejected.** It wasn't.
- **Root cause:** "loop not closed." UCs marked done because component built, not because user-flow verified. Compounded by the QC anti-pattern not being enforced.

### Gap 4 — pilot_signups table no UI
- `fix-pilot-signups-database-table-missing` (2026-03-23) — table created.
- `feat-pilot-signup-invitation-pipeline` (2026-04-22) — invite API created.
- **No UC ever asked for "admin page to view pilot_signups."** The product/PM agent doesn't reason about data lineage (table created → must be exposed somewhere).
- **No detection layer** scans `schema.sql` vs admin pages for orphaned tables.
- **Root cause:** PM is reactive; no schema-driven coverage.

### Gap 5 — Dashboard nav misrouted (Reports/Assignments 404, Settings wrong path)
- **PR #1015** ("Fix navigation — Lead Feed, History, Analytics all route to same page", merged 2026-04-07) — dev exceeded scope. The fix-task asked for 3 nav items to point to distinct pages. Dev added 3 MORE (Reports, Assignments, Settings) without verifying those pages exist.

- **Root cause:** scope creep + string-match test + QC didn't enforce its own anti-pattern.

## 3. Cross-Cutting Genome Failures

These appeared multiple times and are the highest-leverage fixes:

### A. PM review pipeline is broken (P0)
**Symptom:** 60+ `product_reviews` rows with `status='pending'` going back to 2026-03-05. The corresponding PM tasks are `done`. The completion → review-row sync is missing or silently failing.

**Evidence (Postgres):**
```
review_status | task_status | count
pending       | done        | many (UTM tracking 2026-04-29, Stripe E2E 2026-04-20, Trial Aha 2026-04-20, …)
```

**Impact:** PM agent does work, no UCs/decisions are produced from it, downstream loop never fires. ~2 months of PM work effectively shelved.

**Where to fix:** `~/projects/genome/core/realtime-dispatcher.js` (or wherever `_processCompletedReviews` lives) — when a task whose ID is in `product_reviews.task_id` transitions to `done`, parse the completion report's `findings`/`decisions` and persist back to `product_reviews` (status, verdict, findings, decisions_needed). Then `_processCompletedReviews` will pick it up and convert to UCs.

### B. Journey reviews stale (P0)
**Symptom:** 14-day cadence in config; latest completed journey review 2026-03-17 (~47 days ago). 3 pending journey reviews dating back to 2026-03-17 never completed.

**Impact:** The single best detection for "user-facing flow is broken" hasn't run in 7 weeks. All 6 product gaps would have been visible to a journey review of `new-agent-signup`.

**Where to fix:** Find the journey-review scheduler in `~/projects/genome/`; it's either not firing, firing but not creating tasks, or tasks complete without persisting (same root cause as A).

### C. QC anti-pattern not enforced (P1)
**Symptom:** Genome's own QC checklist says "no string-match tests" — yet at least three string-match tests are in main:
- `tests/unit/trial-to-paid-conversion.test.js:84` (`fs.existsSync`)
- `product/lead-response/dashboard/tests/uc-1015-navigation-links.test.js` (string-match on nav source)
- `product/lead-response/dashboard/tests/feat-conversion-call-booking.test.js:42` (`includes('data-testid="..."')`)

**Where to fix:** `~/projects/genome/agents/qc/RULES.md` (or equivalent) — add explicit reject patterns: `fs.existsSync(.*page.tsx)`, `includes('data-testid="…"')` as a sole assertion, `assert(content.includes(...))` without an HTTP fetch. QC prompt should refuse PRs whose new tests match. Add a positive standard: an E2E test must perform an HTTP/page-load assertion, not a file-system or string check.

### D. "Loop not closed" — UCs marked complete with broken flow (P1)
**Symptom:** Multiple UCs in this audit are marked `complete` while the real user-facing behaviour is broken (Gap 3 most clear). Per global CLAUDE.md, this is the named failure mode.

**Where to fix:** `~/projects/genome/core/heartbeat-executor.js → sweepUCCompletions()`. Today it gates UC completion on whether all workflow-step tasks are `done`. Add: when the UC's acceptance includes "user reaches page X" or "flow Y works," run a runtime probe (HTTP follow or Playwright if needed) before flipping status. Minimal version: any UC mentioning a navigation/redirect should require a corresponding E2E test that actually walks the redirect at HTTP level.

### E. Schema-vs-UI orphan detection (P2)
**Symptom:** Gap 4 — `pilot_signups` table created, no UI to view it. Likely other examples (worth scanning).

**Where to fix:** new codebase rule (or genome heartbeat check): for every CREATE TABLE in `database/schema.sql`, look for at least one SELECT against it in `app/admin/**` or admin Express routes. Threshold: 7 days post-creation, no admin SELECT → warning.

### F. Scope-creep detection (P2)
**Symptom:** Gap 5 — PR #1015 added 3 unscoped nav items.

**Where to fix:** QC prompt — when reviewing a PR, list the new files/exports vs the UC's stated scope. If diff touches >N files outside the scope keywords, flag for human or downgrade to "request changes."
