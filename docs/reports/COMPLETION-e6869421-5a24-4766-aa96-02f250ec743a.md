## The Bug

The `replenishQueue()` function in the Genome heartbeat executor was calculating `startStep` only for UCs with status `['stuck', 'in_progress', 'not_started']`. Ready UCs were excluded from this calculation, causing them to always start at step 0. This led to infinite task recreation loops when a UC was in 'ready' status but had already completed some workflow steps.

## The Fix

The fix adds `'ready'` to the status filter in the `replenishQueue()` function:

```javascript
// Before (buggy):
if (['stuck', 'in_progress', 'not_started'].includes(uc.implementation_status)) {

// After (fixed):
if (['stuck', 'in_progress', 'not_started', 'ready'].includes(uc.implementation_status)) {
```

This ensures that ready UCs also have their `startStep` calculated based on completed tasks, preventing duplicate task creation.
