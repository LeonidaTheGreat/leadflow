## Root Cause Analysis

The distribution loop was caused by three separate bugs:

1. **UC Completion Gate Missing** — health check didn't know when UCs were complete, so it kept raising issues
2. **No Task Cooldown** — createDistributionTasks() created tasks every iteration without checking for recent duplicates
3. **Status-Only Loop Dedup** — loop detector only checked status field, which was stale after investigation tasks completed

All three are now fixed.

## How It Works (Post-Fix)

**On Each Heartbeat:**

1. **distribution-collector.js** runs health checks
   - Fetches `completedUcIds` from database
   - For each issue type, checks: `if (completedUcIds.has(linkedUc)) { skip }`
   - Example: if `gtm-landing-page` UC is complete, `no_landing_page` issue is skipped

2. **createDistributionTasks()** runs
   - Before creating a task, queries for tasks created in last 30 min
   - If recent task found: skip creation (cooldown)
   - Query uses timestamp, not status: `.gte('created_at', shortCutoff)`

3. **task-store.js** loop detection
   - When checking for cascading loops, uses: `.gte('created_at', thirtyMinutesAgo)`
   - Prevents false positives from stale status fields
   - Works correctly even if task is in `in_progress` state

**Result:** No more duplicate tasks → No more loops → No more cascade failures
