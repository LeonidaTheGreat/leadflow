## Implementation Details

### What Was Fixed

The distribution health check was creating duplicate "PM: Distribution — Create Landing Page" tasks every heartbeat cycle due to three root causes:

1. **Empty `distribution_channels` table** — The table existed but had no records, so `checkDistributionHealth()` always reported missing landing page
2. **No dedup guard** — Distribution task creation had no window-based deduplication, allowing 3+ identical tasks in 15 minutes
3. **Loop detector with no cooldown** — Loop investigation tasks were created repeatedly because the status check only looked at active tasks, not recent history

### Solutions Applied

- **Genome Fix A:** SQL seed inserted landing page record into `distribution_channels` (idempotent, uses ON CONFLICT)
- **Genome Fix B:** Added 7-day dedup window check before task creation in `distribution-collector.js`
- **Genome Fix C:** Changed loop detector cooldown from "is there an active investigation task" to "was an investigation task created in last 24h"
