## Summary

Fixed two bugs in the Genome heartbeat-executor that caused duplicate "Dev: UC acceptance failed" tasks to be created for UCs in `needs_merge` or `stuck` status.

## Bugs Fixed

### Bug 1: Acceptance checks running for blocked UCs
**Problem:** The heartbeat-executor ran acceptance checks for UCs in `needs_merge` or `stuck` status, creating unnecessary fix tasks even though these UCs were blocked on human intervention or previous failures.

**Fix:** Added a guard clause before the acceptance verification block to skip checks when `uc.implementation_status` is `needs_merge` or `stuck`.

```javascript
// BUG FIX: Skip acceptance checks for UCs in needs_merge or stuck status.
if (uc.implementation_status === 'needs_merge' || uc.implementation_status === 'stuck') {
  console.log(`   ⏭️ UC ${uc.id} — skipping acceptance checks (${uc.implementation_status})`)
  continue
}
```

### Bug 2: Missing cooldown for completed fix tasks
**Problem:** `findTaskByTitle()` excludes done tasks from dedup, so once a fix task completed, the guard was blind and would immediately create a new duplicate task on the next heartbeat.

**Fix:** Added a 4-hour cooldown query for recently-completed fix tasks alongside the existing `findTaskByTitle` check.

```javascript
// BUG FIX: 4-hour cooldown — check for recently completed fix tasks
const fourHoursAgo = new Date(Date.now() - 4 * 60 * 60 * 1000).toISOString()
const { data: recentlyDone } = await this.store.supabase
  .from('tasks').select('id, updated_at')
  .eq('project_id', this.projectId)
  .eq('title', failTitle)
  .eq('status', 'done')
  .gte('updated_at', fourHoursAgo)
  .limit(1)
if (recentlyDone?.length > 0) {
  console.log(`   ⏭️ UC ${uc.id} — acceptance fix task completed recently (cooldown: 4h)`)
  continue
}
```
