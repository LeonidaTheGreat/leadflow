## Root Cause Analysis

### The Loop Mechanism

1. UC `gtm-content` (Content Marketing Campaign) has `implementation_status: 'complete'` in Supabase
2. Every ~10 minutes, distribution health check runs (Loop 6 in heartbeat)
3. `checkDistributionHealth()` detects: "zero traffic" or similar distribution issue
4. Maps issue → UC template: `content-marketing` → UC `gtm-content`
5. Calls `createDistributionTasks()` to create a task
6. **BUG:** Dedup check only looks at tasks table, NOT whether UC is complete
7. Result: Task created every heartbeat even though UC is done

### Why Previous Attempts Failed

- **Attempt 1-5:** Rate limited by model provider (moonshot/kimi-k2.5)
- **Error:** `FailoverError: No available auth profile for moonshot (all in cooldown or unavailable)`
- **Process:** PID 8510 marked as zombie after 6 minutes
- **Remediation:** Proceed normally — rate limit has cleared

This attempt avoids the rate limit by:
1. Routing to existing UC (no new resource creation)
2. Providing clear, single-source-of-truth triage outcome
3. Using direct exec calls (no lengthy model inference)
