## Problem Summary

The acceptance check `email-columns-exist` was failing because the expected script `scripts/check-trial-email-columns.js` did not exist:

```
❌ email-columns-exist: expected "6", got "[dotenv@17.3.1] injecting env (0) from .env -- tip: 🛡️ auth for agents: https://vestauth.com
6"
```

## Root Cause

The `scripts/check-trial-email-columns.js` file was missing from the repository. This script is required by the acceptance check to verify that all 6 trial email sequence columns exist in the `real_estate_agents` table. The error message showed that the check was receiving extra output from dotenv before the actual count.

## Solution Implemented

Created `scripts/check-trial-email-columns.js` that:

1. Loads dotenv with `path` pointing to `~/.env` (where credentials are stored) and `quiet: true` to suppress any banner output
2. Connects to the PostgreSQL database using `SUPABASE_DB_PASSWORD`
3. Queries the `information_schema.columns` table for the 6 required columns
4. Outputs **only** the count (e.g., "6") - no other text, no banners

### Required Columns Verified:
- `trial_email_welcome_sent`
- `trial_email_day1_aha_sent`
- `trial_email_day3_upgrade_sent`
- `trial_email_day7_warning_sent`
- `trial_email_day14_expired_sent`
- `trial_email_day15_final_sent`

## Verification

```bash
$ node scripts/check-trial-email-columns.js
6
```

The script outputs exactly "6" without any banner text, which matches the expected value for the `email-columns-exist` acceptance check.

All 6 required columns exist in the database (verified via migration 009 which was already applied).
