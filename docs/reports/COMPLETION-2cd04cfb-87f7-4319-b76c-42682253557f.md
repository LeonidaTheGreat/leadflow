## Problem Summary

The acceptance check `email-columns-exist` was failing because the output was polluted with dotenv debug information:

```
❌ email-columns-exist: expected "6", got "[dotenv@17.3.1] injecting env (0) from .env -- tip: ⚙️  override existing env vars with { override: true }
6"
```

## Root Cause

The `.env.local` and `~/.env` files had a malformed line where `SUPABASE_DB_PASSWORD` was concatenated directly to the end of `PRODUCT_MANAGER_BOT_TOKEN` without a newline:

```
PRODUCT_MANAGER_BOT_TOKEN=8786967558:AAGobt-_fyHBcvku_j1gpZJgLedRstyn_LISUPABASE_DB_PASSWORD=a$_h9jkyPv8G&Gp
```

This caused dotenv to output debug information when parsing the file, which polluted the acceptance check output.

## Solution Implemented

### 1. Fixed `.env.local` File

**Before:**
```
PRODUCT_MANAGER_BOT_TOKEN=8786967558:AAGobt-_fyHBcvku_j1gpZJgLedRstyn_LISUPABASE_DB_PASSWORD=a$_h9jkyPv8G&Gp
```

**After:**
```
PRODUCT_MANAGER_BOT_TOKEN=8786967558:AAGobt-_fyHBcvku_j1gpZJgLedRstyn_LI
SUPABASE_DB_PASSWORD=a$_h9jkyPv8G&Gp
```

### 2. Fixed `~/.env` File

Applied the same fix to the system-level `.env` file in the home directory.
