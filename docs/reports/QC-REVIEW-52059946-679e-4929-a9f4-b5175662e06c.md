## Issues Found

### BLOCKING: Security — NEXT_PUBLIC_ key used as server auth secret

**File:** `app/api/internal/send-activation-emails/route.ts`, line 20

```typescript
const secret = (process.env.API_SECRET_KEY || process.env.NEXT_PUBLIC_API_KEY || '').trim()
```

`NEXT_PUBLIC_` prefixed env vars are bundled into the client-side JavaScript and exposed to
any browser. Using one as a server-side authentication secret means anyone who loads the
page can read the key from the browser bundle and call the batch email endpoint
(`POST /api/internal/send-activation-emails`) without authorization.

This pattern also exists in `lib/db.ts` (pre-existing) but that file was not introduced by
this PR. This endpoint IS introduced by this PR and must be fixed.

**Fix:** Remove the `NEXT_PUBLIC_API_KEY` fallback:
```typescript
const secret = (process.env.API_SECRET_KEY || '').trim()
```

Ensure `API_SECRET_KEY` is set in Vercel project settings as a server-only env var.

### NON-BLOCKING: Live Vercel 500 on batch endpoint

The deployed Vercel app returns HTTP 500 for `POST /api/internal/send-activation-emails`
even for unauthenticated requests. The auth check runs before DB access and should return
401, not 500. This is likely a Vercel env var issue (`API_SECRET_KEY` not set in Vercel,
causing the `NEXT_PUBLIC_API_KEY` fallback to also be empty, which causes `isAuthorized()`
to return false — but the 500 suggests the module itself fails to load). This is related
to the security issue above (once `NEXT_PUBLIC_API_KEY` fallback is removed and
`API_SECRET_KEY` is set in Vercel, this should resolve). Not blocking independently but
the security fix is required.

### NON-BLOCKING: Unrelated noise in diff

This branch contains a large amount of diff unrelated to this UC (landing page changes,
funnel diagnostics, pilot campaigns, trial email sequences, etc.). These are from prior
dev branches that merged into this branch's base. The QC review scope is limited to the
feature commit (d92a8c2). The noise does not affect the verdict but note that `git diff main`
shows 65+ files changed while the actual feature is 5 files.
