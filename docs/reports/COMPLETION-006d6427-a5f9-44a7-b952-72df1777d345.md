```javascript
const fortyEightHoursAgo = new Date(Date.now() - 48 * 60 * 60 * 1000)
const recentMatches = existingTasks.filter(t => {
  if (t.title !== title) return false
  if (!['ready', 'in_progress', 'spawned'].includes(t.status)) return false
  const createdAt = new Date(t.created_at)
  return createdAt > fortyEightHoursAgo
})
if (recentMatches.length > 0) {

  results.skipped++
  continue
}
```

## Technical Details

### Root Cause (Original Problem)
The revenue alert system was creating duplicate tasks on every heartbeat cycle because:
1. Loop detector lacked cooldown between meta-task creations
2. Revenue collector didn't check for existing active tasks
3. No auto-cleanup for stuck tasks
4. Auth failures cascaded into new task creation

### Solution Architecture
Four independent fixes at different layers:
1. **Temporal fix:** 24h cooldown prevents re-triggering
2. **Dedup fix:** Query existing tasks before creation
3. **Lifecycle fix:** Auto-archive stale tasks
4. **Error handling fix:** Catch and log auth failures

### Why This Works
- **Idempotency:** Same goal state → same task (no duplicates)
- **Resilience:** Failed tasks don't cause cascading creation
- **Cleanup:** Stale tasks don't block future alerts
- **Observability:** All decisions logged for diagnostics
